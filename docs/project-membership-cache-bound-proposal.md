# 提案：给对端缓存判定加服务端上界，把 `member_epoch` 降级为优化

> **状态：待定，需要派发方（对端消费方）同意。** 本文档只描述方案与代价，不含实现。
> 与 [`project-member-epoch-rollout.md`](./project-member-epoch-rollout.md) 配套阅读：
> 那份描述当前契约，这份描述为什么当前契约不足以单独承担正确性。

## 1. 结论先行

`member_epoch` 无法成为充分的失效信号，**原因不是实现缺陷，是键控不匹配**：它按
project 键控，而决定答案的四个轴里有一个是 per-user 的。这不是纪律问题，再多轮 review
也修不好。

建议把正确性从「epoch 一致 ⇒ 缓存有效」改成「缓存有效期由服务端给上界」，`member_epoch`
保留为**窗口内的快路径优化**。

## 2. 为什么是结构问题

`_verify` 的答案由四个事实决定。逐轴看失效通道：

| 轴 | 答案怎么来 | `epochs` 怎么反映 |
|---|---|---|
| `octo_project_member.status/removing` | 项目侧写入 | 同事务 bump —— 结构闭合 |
| `space_member.status`（双向） | Space 合取 | 靠每个写入方记得跑事务步骤 |
| `space.status` | 读时 fold | `ProjectEpochsInSpace` 读时折成 absent sentinel —— 结构闭合 |
| `user.status` / `is_destroy` | 读时合取 | **无法反映** |

第四行是决定性的。封禁 Alice 是一个 per-user 事实；要让它移动 epoch，就得让「任何含
Alice 的项目」的 epoch 都动 —— 那 epoch 就不再表示「这个项目的成员集变了」，而是「任何
相关用户的任何属性变了」，等于给每个项目装上全体成员的写放大。**一个 per-project 的整数
无法表达一个 per-user 的变化。**

这一轴目前记录为「已知偏离」，其正确性依赖 `project-member-epoch-rollout.md` §
「账号轴」里那句对对端的要求：*对缓存的判定加一个独立于 epoch 的上限 TTL*。也就是说，
**当前设计已经在依赖对端 TTL，只是没写进契约、没有任何东西能观测它。**

第二行则是本分支第 5、6、7、9、11、12 轮反复找到的同一类：新写入方漏发信号、或发了但用
错标识符。第 12 轮的类型化修复（`SeatRef`）让「传错标识符」编译不过，但它管不到
「有人在别处新开一条改 `space_member` 的路径」。

## 3. 方案

### 3.1 应答带服务端上界

`verifyResponse` / `epochsResponse` 增加一个服务端设定的字段：

```
max_age_seconds: <int>     // 这个答案最多可以被缓存这么久
```

语义：**到期必须重新 `_verify`**，与 epoch 是否变化无关。

### 3.2 epoch 快路径限定在窗口内

`epochs` 返回的值带签发时刻。对端可以继续用「epoch 没变 → 跳过完整 `_verify`」省开销，
但**只在窗口内有效**；超窗后服务端不再回答这个便宜问题，必须走完整 `_verify`。

这一条是方案的关键：它把「请对端自觉实现 TTL」从一句请求变成**服务端可执行**的东西 ——
想走便宜路径就必须按时回来。一个完全摆烂、只缓存 `true` 的对端谁也拦不住，但那已经不是
TTL 问题而是对端不实现契约，且**可观测**（见 §5）。

### 3.3 于是四个轴统一

漏一次 bump 的后果从「无限期陈旧授权」降为「最多陈旧 `max_age_seconds`」。这对**已经找到
的**每一个缺陷成立，也对**还没找到的**成立 —— 在连续三轮「上一轮修复开出下一轮 P1」之后，
这是我唯一愿意做的假设。

账号轴不再是偏离，它和其它三轴一样受同一个上界约束。

## 4. 对端需要改什么

1. 读取并遵守 `max_age_seconds`，到期强制重新 `_verify`。
2. 缓存条目记录签发时刻；epoch 快路径只在窗口内使用。
3. 窗口内 epoch 变化仍然立即失效（现有行为不变）。

## 5. 启用门禁：从「承诺」变成「实测」

服务端能看见每个对端的请求流，因此可以直接度量其复查间隔：

- 指标：按对端标识统计 `_verify` 间隔的 p99；
- 门禁：**在观测到该对端的复查间隔稳定 ≤ `max_age_seconds` 之前，不要设置
  `OCTO_MEMBERSHIP_INTERNAL_TOKEN`。**

这替换掉当前那条「等对端实现 TTL」的口头前置条件 —— 同一个门禁，但可验证。

## 6. 代价

- **对端多一档定期复查。** 窗口内仍走 epoch 快路径，所以增量是每窗口一次轻量 `epochs`
  轮询（单列读）+ 窗口到期时一次完整 `_verify`。`max_age_seconds` 是旋钮。
- **`max_age_seconds` 取值需要定。** 建议从 30s 起，按实测 `_verify` 负载调整。撤销的
  最坏陈旧时间等于这个值 —— 与任何缓存同一量级，且**当前账号轴的实际陈旧时间是无上界的**，
  所以这是收紧而不是放松。
- **不是一次纯服务端变更。** 需要派发方改代码，因此需要先达成一致。

## 7. 考虑过并否决的替代方案

| 方案 | 为什么不选 |
|---|---|
| **全量 collation 转换**（`0900_ai_ci` → `general_ci`） | 该做，但它是跨 8+ 张表的运维窗口，需要逐个唯一索引做碰撞预检（见 `sql/20260904000001_project_core.sql` 的说明）。**不该成为本 PR 的前置**；上了本方案之后它也不再是正确性前提，降级为技术债。 |
| **DB trigger 自动 bump** | 确实能让「忘记 bump」不可表达，且 trigger 拿到的是 `NEW.uid`（存的字节），连标识符问题也一并消除。但它把一个跨表写入藏进隐式路径，而这条分支花了四轮在锁序上 —— 把锁序变成不可见的，是拿已踩过的坑换没踩过的坑。它也管不到第四轴（封禁不写 `space_member`）。 |
| **单一写入漏斗 + 禁止式源码 guard** | 能闭合「某个写入方不发信号」这一类，但同样管不到第四轴。census 自己的头注释就承认「仪器无法在它表达不了的东西上失败」，而四个轴里它只能表达一个。 |
| **把 epoch 改成读时派生** | 概念上最干净（答案与失效信号出自同一次查询），但 `epochs` 是 per-project 的，要派生就得跨四张表聚合该项目全体成员 —— 生产上那正是会撞 1267 的形状，且开销不可接受。 |

## 8. 与本 PR 的关系

本 PR **不实现**本提案。它做的是：把标识符类型化，使「传错拼写」编译不过；并把
`octo_project_member` 的孤儿化这一**数据完整性**缺陷修掉 —— 那一条任何 TTL 都不修。

本提案要解决的是剩下那部分：**epoch 作为唯一失效通道，对第四轴在结构上不成立，对前三轴
依赖每一处写入都不出错。**
